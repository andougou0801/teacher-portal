## やること

### 1. 承認済みの案を実装する

`docs/backlog.md` に状態が「承認済み」の案があれば実装します（なければ飛ばす）。

1. `git fetch origin`
2. `git switch -c auto/<今日の日付>-<短い名前> origin/master`
3. 実装する
4. `npm run lint` と `npm run build` を実行し、成功を確認する
   （失敗したらpushしない。EPERMで落ちたら `.next` を消して再実行）
5. `public/tools/*.html` を追加・編集した場合は、デスクトップに元ファイルを置き、
   `mklink /H` でハードリンクを張る（`fsutil hardlink list` でリンク数2を確認）。
   **どちらを編集したかでコピーの向きが変わる**ので注意（CLAUDE.md参照）
6. 意図して変更したファイルだけを `git add`（`git add -A` は使わない）
7. 日本語のメッセージでコミットし、`git push -u origin auto/<...>`
8. バックログの状態を「確認待ち」にし、**ブランチ名を報告に書く**

### 2. チェック担当が確認する

実装したものがあれば、**実装したのとは別のサブエージェント**に確認させます。
動作・スマホ表示（375px）・リンク切れ・誤字・個人情報ルール違反。
**計算をするツールは、答えが正しいかを実際に数値で検算させてください。**
**印刷するツールは、A4一枚に収まるかを `offsetHeight` で実測させてください**
（`getBoundingClientRect` は縮小表示の影響を受けるので使わない。CLAUDE.md参照）。

### 3. 新しい提案を考える（最大3件）

教員の困りごとや他サイトの便利機能を調べ、足りないものを提案します。
`docs/backlog.md` の「改良の提案」に追加。IDは**既にある一番大きい番号の次**から
（重複しないよう、追加前に必ず今のIDを確認すること）。状態は「提案中」。
それぞれ「どの先生の、どんな困りごとを解決するか」を必ず書く。

`Get-Date -Format yyyy-MM-dd` で確かめます（Git Bash の `date` はずれる）。

やったこと／ブランチ名／チェック結果／追加した提案／**うまくいかなかったこと**を正直に。
