# エージェントの役割分担（ゲーム作りの職能）

「かずのまち」は、ゲーム会社なら何人もでやる仕事を、**役職ごとにエージェントを分けて**
進めている。次に会議を開くときは、この表から必要な役だけを選んで呼べばよい。

## 役の一覧

| 役職 | ひとことで言うと | 何を出す役か |
| --- | --- | --- |
| **プロデューサー** | 何を作り、何を作らないか決める人 | 版ごとの計画・優先順位・やらないことの決定・リスクの備え |
| **ゲームディレクター** | 面白さの最終判断をする人 | 全体の一貫性。意見が割れたときの決着（いまは運営者＋まとめ役が兼任） |
| **ゲームプランナー（企画）** | 遊びのアイデアを出す人 | 世界観・物語・遊びの流れ・飽きさせない仕掛け |
| **システムデザイナー** | 仕組みと数値を設計する人 | 材料・コスト・成長の数値。**机上ではなく計算で破綻を見つける** |
| **レベルデザイナー** | 進み方を設計する人 | 12週の流れ・1回の問題数・山場の置き方・つまずいた子への分岐 |
| **学習デザイナー**（この企画に固有） | 学びの質を守る人 | 学習指導要領との対応・復習の間隔・難易度の調整 |
| **コンテンツ制作（問題係）** | 中身を量産する人 | 問題データ。単元を分担して同時に作る |
| **アートディレクター** | 絵の責任者 | キャラクター・建物・色。**見分けやすさ**を作る |
| **サウンドデザイナー** | 音の責任者 | 効果音（音源ファイルを置けないので Web Audio で作る） |
| **UXライター** | 画面のことばの責任者 | 文言の統一・読みやすさ・禁止語の点検 |
| **テクニカルディレクター（エンジニア）** | 技術の責任者 | ファイル構成・性能・保存・端末ごとの落とし穴 |
| **QAリード** | 品質を守る人 | テスト項目表・壊れやすい所・回帰テスト |
| **安全・コンプライアンス** | 止める人 | 依存を生まない設計・個人情報・健康。**他の役を押し返す役** |
| **ユーザー代表（子ども役・先生役）** | 使う人の本音 | 「つまらない」「教室で回らない」を遠慮なく言う |
| **チェック担当** | 実装とは別の目 | 直したと言っているものが本当に直っているかを確かめる |

## 使い分け

- **新しいものを企画するとき**：プランナー＋学習デザイナー＋アート＋子ども役＋先生役＋安全
- **数値がおかしいと思ったとき**：システムデザイナー（**必ず計算させる**。感想では見つからない）
- **作ったものを点検するとき**：チェック担当＋QA＋子ども役＋先生役
- **量産するとき**：問題係を単元ごとに分けて同時に走らせる
- **公開の前**：QAの回帰テスト10項目＋プロデューサーの「完成の定義」

**かならず入れる役**：安全・コンプライアンス（依存と個人情報の歯止め）、
子ども役と先生役（使う人の本音）、チェック担当（実装者と別の目）。

**広げる順番**：学年を上げる前に小1を通年で終わらせる。次は同じ学年の国語
（読める字の制限を作り直さなくてよい）。学年を上げるのは最後。

### やらないと決めたこと

| やらないこと | 理由 |
| --- | --- |
| サーバー・アカウント・クラス一覧 | 個人情報を預かる責任と障害対応を1人では持てない |
| 友だちの町を見る・共有する | 比べ合いを生み、「依存を生まない」という大前提に反する |
| 他学年・他教科の同時着手 | 小1通年が終わる前に広げると全部が半端になる |

### 1人＋AIで続けるための進め方

- 1回＝90分まで。1テーマ1ブランチ。終わりに必ず `progress.md` を更新してから閉じる
- **平日は「コードを触らない回」**（問題データのJSONだけ、30分で1スキル分）
- **週末に90分×1回だけコードを触る**。触った回は必ず1回通しで動かす
- 1回の会議は3役まで。役を増やすほど判断が運営者に戻ってくる
