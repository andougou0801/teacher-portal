# 第1回 企画会議（2026-11-21）

通年型の勉強ゲーム（仮称）の立ち上げ会議。9つの役を同時に走らせ、それぞれの意見を集めた。

## 運営者が決めたこと（会議の前提）

| 項目 | 決定 |
| --- | --- |
| 最初に作る範囲 | 小学1年生・算数・1学期ぶん（そのあと学年を順に上げていく） |

| 1日の目安 | 15分 |
| 世界観 | 町づくり ＋ モンスターを倒してアイテムを手に入れる ＋ アバター（自分）を強化 |

## 子ども役の意見（小1の本音）

**やりたいと思うところ**
- モンスターを倒せる。自分だけの町ができる。アバターを強くして友だちに見せたい。

**つまらなそう・飽きそうなところ**
- 毎日同じ算数の問題だと「また10までのたし算か」になる。学校のプリントと同じ感じがするのがいや。
- 建物が増えるだけでは面白くない。動いたり話したりしないなら、すぐ見なくなる。
- 自分が強くなっても、強い相手が出てこないと強くなった意味がない。

**つまずくところ**
- 字が読めない。「けんせつ」「そうび」「アイテム」は読めないし意味も分からない。ひらがなでも長いと途中でやめる。**全部に音声の読み上げがほしい。**
- ボタンが小さい・近いと押し間違える。「もどる」の場所が分からないと先生を呼ぶしかない。
- 数字を入れるとき、小さいキーボードが出ると分からない。大きいボタンで選びたい。
- ドラッグして建物を置くのは手がふるえてうまくできない。
- 15分で途中で終わると、どこまでやったか分からなくなる。

**くじ引きがないことについて**
- ガチャは知っている（兄が遊んでいる）。無くてもいやではない。でも「何が出るかな」のドキドキはほしい。
  → 宝箱を開けて中身が見える、たまにキラキラのレアがある、といった形。
  （※ 安全・健康担当の「ランダム報酬の禁止」とぶつかる。下の「ぶつかった点」で扱う）

**15分で終わりと言われたとき**
- 「えー、もっとやりたい」になる。でも無理やり切られるのはいや。
  「あとすこしでおわりだよ」とキャラクターが教えてくれるのがいい。
- 終わるときに「きょうは3体たおしたね」「あしたは新しい友だちが来るよ」と言われたら、また明日やりたい。
  終わったあと、町のようすが少し変わっているとうれしい。

**モンスターについて**
- 倒すのは楽しい。でも**間違えて自分がやられるのはすごくいや。**「ぼくが間違えたからだ」と悲しくなる。
  算数が苦手な子は泣いてしまう。やられるのではなく「おしい！もういっかい！」とヒントが出る形がいい。
- モンスターは倒すだけでなく**仲間になってくれる**のが好き。

**町づくりについて**
- 建物が増えるだけではうれしくない。うれしいのは**自分が選んだものが動くこと**
  （家に人が住んであいさつする、犬が走る、夜になったら明かりがつく）。
  好きな色にぬったり名前をつけたりできるのがうれしい。

**これだけは入れてほしい**
- モンスターが仲間になって、町でいっしょに暮らして、自分の名前を呼んでくれること。

## 先生役の意見（小1担任・30人学級の実態）

**いつ使えるか**
- 朝の時間（10〜15分）がいちばん現実的。ただし登校のずれと準備で、実際に遊べるのは8〜10分。
- 算数の授業の最後5〜10分の「ふくしゅう」なら使える。導入や説明には使えない。
- すきま時間（3〜5分）は、起動して終わる。使うなら「早く終わった子だけ」。
- 家庭学習には使えない（記録が学校のiPadの中だけだと、家では続きができない）。

**30人で一斉に始めると起きること**
- 端末を配ってURLを開くまでで5〜8分。フォルダや別のアプリを開く子が3〜5人。
- 止まる子は30人中5〜8人。音が一斉に鳴って先生の指示が通らない。
- **ニックネーム入力でつまずくのは10人前後**（ひらがな・変換・キーボードの切替）。
- 初回は15分のほとんどが操作説明で終わる。

**「かいほうコード」方式は現実的か → 1年生には無理**
- 1学期の1年生はひらがなも途中で、英数字は読めない。大文字小文字・0とOの打ち間違いで10人以上が止まる。
- 黒板に書く運用も、写し間違いで回らない。
- 代わりの案：①最初から全ステージを開放し、先生は「いまやるところ」を1回だけ指定する（子どもは触らない）
  ②4桁以下の数字、または絵のボタンを3つ押す程度にする
  ③ステージは子どもの進度で自動開放し、先生はほぼ関与しない

**進み具合が見えないことへの対応**
- つまずいている子が分からないのは困る。評価の根拠にはできない。
- ただし「練習・ふくしゅう」と割り切れば使える。
- 代わりに足りるもの：子どもの画面に「きょうは◯もんせいかい」を**大きく**出す。
  先生は机間巡視で見るだけで分かる。紙の「がんばりカード」を印刷できる程度でよい。

**端末を共有する学校での問題**
- 「今日はどの子がどの台か」は固定でない。別の子のデータで始まる・上書きするが普通に起きる。
- 1年生は自分のニックネームを覚えていない／打てない。
- **対策：ニックネーム入力ではなく、出席番号（1〜30）とキャラクターの絵を選ぶ方式。**

**あると助かる機能（3つ）**
1. ひらがな・大きなボタン・**音声読み上げ**（問題文を耳で聞ける）
2. 起動したら1タップで続きから始まる（名前選択も絵と番号で）
3. 15分で自動的に区切りが付く（時間管理が先生の手を離れる）

**入れないでほしいもの**
- 先生が子どもごとに設定する機能／ランキング・対戦・ガチャ／自由入力の名前・チャット／
  課金や広告に見える要素／長い待ちアニメ／データのバックアップ手順（先生が代行することになる）

**保護者から来そうな問い合わせ**
- 進み具合が分からない／家でできない／データが消えた／勉強になっているのか／ずっとやりたがる／個人情報は大丈夫か

**総評**
- 実用になるのは「朝の10分か授業の最後」「ペアまたは少人数」「**コード入力なし**」の3点を守った場合。
  一斉30人・コード入力方式のままでは、初回は授業が崩壊する。

## ゲームデザイナーの意見

**世界観**：数が消えてしまった町に、子どもが「かず」を取りもどして町を作り直していく話。町の外には数を食べてしまう「もやもや」がいて、たたかって材料を取りもどす。

**名前の案**：かずのまち／かぞえのおか／すうのたね → 推しは **かずのまち**（教科を変えて横に増やせる。姉妹作に「ことばのまち」を並べられる）

**15分の流れ**

1. 町の画面（〜20秒）：今日の「しごと」が1つだけ光る
2. おでかけ（1タップ）：地図に今日の3ステージ（各約3分）。順番は子どもが選べる
3. たたかい（3分×3）：1ステージ＝6〜8問。1問1画面、絵で出題、答えはタップか入力
4. 材料をもらう：**解いた問題の種類で決まった材料が必ず出る**（あわせていくつ→いた／のこりはいくつ→いし）
5. 町にもどって建てる（2〜3分）：材料がそろった建物が光る→1タップで建つ。町の人が1人増える
6. アバター強化（30秒）：余った材料で装備を1つ強くする
7. おわりのカード：「きょう できるように なったこと」を絵＋ひらがな2〜3行

**3要素のつなげ方**

- **目的＝町づくり**（1年かけて育つ唯一の長期目標。これだけが「貯まる」実感を持つ）
- **手段＝モンスター**（学習そのものの入れ物。材料は確率ではなく問題の種類と達成で確定。「運」の代わりに**選択**で変化を作る＝どの材料を取りに行くか子どもが決める）
- **橋渡し＝アバター強化**（町は遅く育つので、15分の中の即時の手応えを担う。能力の上下はつけず、見た目と補助機能にとどめる）

**1年の流れ**

- 1学期：4月＝10までの数／5月＝いくつといくつ（材料が2種に増え「選んで取りに行く」が始まる）／6月＝あわせていくつ・のこりはいくつ（地区が「かわべ」に拡張）／7月＝10より大きい数・ながさくらべ、学期末に**まちびらき**
- 2学期：くり上がり・くり下がり、かたち、とけい、ひろさ。地区は「やま」「みなと」
- 3学期：大きい数、1年のふりかえり。3月は「まちのおまつり」
- 飽きさせない仕掛けは**新ルールではなく、地区の追加・季節の色・学期末の式典の3本に限定**

**外せない演出3つ**

1. 押した瞬間の返り（transform: scale だけ＋Web Audioで60msの音。これで「アプリらしさ」の8割）
2. 連続正解で音階が上がる（競争ではなく自分の積み上げの音。間違えても音を下げない）
3. 建物が育つ1.2秒（下から伸びて少し跳ねる。1日1回しか見られないので飽きない）

**心配な点**：ステージ途中で15分が来るとおわりのカードが出ない／確定報酬は先が読めて退屈になりうる（毎日の選択は3つまで）／進度の差が町の大きさに出る（建物数より地区の色・かざりで差を出す）／localStorageの消失／演出の長さ（初回は長く、2回目以降は短縮で折り合う）

## 学習の専門家の意見

**間違えた問題の再出題**：不正解 → **3問後**に1回、正解できたら**12問後**に確認の1回。2回連続正解でその日は終了。2回目も不正解なら、数図・具体物つきの易しい形で3問後にもう1回（1日1問につき最大3回）。「また同じのだ」対策は**同型別数字**（7+5→8+5）。世界観では「にげたモンスターがもどってきた！」。×印は出さず「もうすこし」＋正答を3秒表示。

**間隔をあけた復習**：**日数ベースを主、開けなかった日は繰り越し**。段階は stage0→1日、1→2日、2→4日、3→7日、4→14日、5→30日。正解で+1、不正解で−1（下限1日後）。1回の復習枠は**上限8問**、期限超過が大きい順。管理の単位は「1問」ではなく**スキル**（小1算数1学期で30〜60個）。保存は `nextDue:"2026-11-21"` と `stage` だけで**時刻は使わない**（端末の時計のずれ対策）。前回より前の日付で起動したら、その日は復習なしで新規だけ。

**難易度の自動調整**：スキルごとに level 1〜5。

- 上げる：直近5問の正答率80%以上**かつ**連続正解3問 → +1（1回で最大2段階、前回と今回の2回続けて条件を満たしたときだけ）
- 下げる：連続2問不正解で即 −1。直近5問の正答率50%未満でも −1（1回1度まで）。下限1
- level+1は「すこしつよいモンスター」として**任意提示**。挑んで倒せなくてもアイテムは半分もらえる
- 折れ防止：その回の正答率が60%を下回ったら、残りはできるレベルに固定して**「できた」で終わらせる**

**制限時間は入れない**（小1は読む速さの差が大きく、計算力ではなく読字速度を測ってしまう。算数が苦手な子にいちばん強く効いてしまう）。応答時間は記録するが見せない。標準12秒の3倍（36秒）を超えたら、カウントダウンなしで「ヒントみる？」を静かに出す。

**15分の構成（計35〜40問）**：ウォームアップ5問 → 復習8問 → 新しい内容（例示2問＋練習8〜10問）→ 間違い直し6問 → 挑戦3問（任意）→ まとめ2〜3問（必ず成功で終える）。**1問終わるごとに保存**。

**「今日できるようになったこと」**：動詞で1〜2文（「10をこえるたしざんが じぶんで できた」）。証拠に**今日できた一番むずかしい問題を1つそのまま表示**。評価の言葉は3種類だけ（はじめてできた／まえよりはやくできた／ばっちりおぼえた）。点数・正答率・順位は出さない。できたスキル1つ＝町の建物パーツ1つにして、町がそのまま「できたことの履歴」になる。

**保存データ**：`skills[skillId]` に level / stage / nextDue / seen / correct / last5（直近5問の正誤を5ビット）/ bestMs / firstClearedOn（1スキル約60バイト、60スキルで4KB弱）。`days[]` は1日1行、直近60日のみ。**1問ごとの全ログは保存しない**（その日のセッション中だけメモリに置き、終了時に集約して捨てる）。

**心配な点**：端末共有で記録が混ざる／「Webサイトデータを消去」で全部消える（学期末のJSON書き出しを必須に）／長期休み明けに復習の期限超過が一斉に来る（上限8問・古い順で2週間かけて消化する設計だと先生に説明が必要）／文字が読めない子（読み上げは不安定なので、問題文は数字と図で成立する最小文字数にする）

## アバター・報酬システム担当の意見

**アバター**：伸びるのは4つのちからだけ（かぞえる／くらべる／かたち／よみとく）。**レベル＝その単元で「できた」になったミニ目標の数**。経験値バーのような間接的な数は使わない。見せ方は数字ではなく**見た目の変化**（Lv3でぼうし、Lv6でマント、Lv10でつえ）。画面には「かぞえるちから ★★★☆☆」の星5段階で出し、内部のレベルは隠す。

**アイテム**：どうぐ12種（ヒント・教具の呼び出しのみ）／みにつけるもの約20種（見た目だけ）／ざいりょう4種（木・石・ガラス・ねんど）／ずかんのたね。**入手は全て確定**。ステージ入口に「クリアすると〈すうじせんのつえ〉がもらえます」と**事前表示**（運がないから予告できる）。ざいりょうは正答1問＝1個、1回15分の上限は12個。

**モンスター**：「まちがいのもと」という設定。倒す＝その問題タイプを3回続けて正しく解くこと。**負けは作らない**（子ども側にHPも制限時間も置かない）。間違えたらモンスターが「へんしん」して同じ型を出し直す。ただし無条件に正解扱いにもしない。3回間違えた型は①ヒント強制表示 ②その日は「またこんどね」で退場 ③後日もう一度出す（間隔反復）として記録する。

**町づくり**：建物は学習領域に対応（かずの家／たしざんの工場／ひきざんの倉庫／かたちの広場／はかりの塔／ことばの橋）。**1学期で6棟**。建てると①その建物から復習問題が出る ②住人が1人増える ③装備が1つ解放。コストは固定（家＝木20、塔＝石30）。1年で20〜24棟＋広場3つ。

**図鑑・称号**：図鑑3冊66種（いきもの24／どうぐ18／たてもの24）、称号30個（すべて「できるようになったこと」の名前）。**取りこぼしはいつでも後から回収できる**（期間限定を作らない）。

**ペース**：1回15分＝問題15〜20問 → ざいりょう最大12個、ミニ目標1〜2個、図鑑の生き物1体。1週間（5回）＝建物1棟＋称号1つ＋アバターLv+2。1学期（約60回）＝建物6棟、図鑑20体、称号8個、装備6個。インフレ防止は、取得上限（12個/回）とコスト（20〜30個）を**年間通して変えない**こと。後半の魅力は数の伸びではなく**種類の増加**で出す。

**歯止め**：1日の「きょうのぶん」は1セット。終わると町の完成アニメが流れ、それ以降は**れんしゅうモード**（報酬は出ないが記録に○はつく）。ガッカリさせない工夫は、止めるのではなく**明日の予告を見せる**こと（「あしたは〈はかりの塔〉がたてられます」）。連続日数・最終プレイ日は一切表示しない。

**心配な点**：localStorageは消える（JSON書き出し＋称号を紙で貼る運用の併用）／装備の効果のジレンマ（学習支援を強くすると練習にならず、弱いと小1には違いが伝わらない。「ヒントつきでできた」と別記録にする案）／図鑑66種をSVGで描くと33時間かかる（パーツ組み合わせ方式が前提）／遅い子の町が育たない（正答数だけでなく「取り組んだ問題数」にも少量のざいりょうを出すか要相談）

## UI・アート担当の意見

**画面は8つ**：はじめ／まち（ホーム）／たたかう／けっか／アバター／たてもの／きろく／せってい

**流れ**：はじめ → まち。**まちが唯一のハブ**で、他7画面はまちから1タップ。全画面の左上に「← まちへ」（64×64px、同じ位置・同じ色）だけを置く。階層は2段まで。たたかう → けっか → まち は一本道（けっかには「つぎへ」だけ）。**戻る導線は常に1つ、常に同じ場所**。

**低学年向けの数値**

- タップ領域：最小 **64×64px**、主要ボタンは **80×80px**、隣のボタンとの間隔 **16px以上**
- 文字：問題の数字 **88px/bold**、ボタン **26px**、本文 **22px**、最小 **20px**（iOSのズーム回避で16px未満は禁止）
- 1画面のボタンは最大4つ（まちだけ5つ＋建物タップ）
- `line-height: 1.8` ／ `letter-spacing: 0.04em` ／ 1行はひらがな14文字以内
- コントラスト：文字4.5:1以上、主ボタン7:1、アイコン・枠線も3:1以上

**色**：クリーム地＋木と土の「てづくりのまち」。原色のベタ塗りは避ける。背景 `#FDF6E8` ／カード `#FFFFFF` ／文字 `#2B2A28` ／そら `#4FA3E3` ／くさ `#5BBF6A` ／つち `#C98A4B` ／こはく `#F2B23C` ／たたかう `#FF7A45` ／せいかい `#1F8F3C` ／まちがい `#D94B3F`。角丸22px（ボタン28px）、輪郭 `3px solid` の濃色、影は `0 5px 0` の板影（押すと4px沈む）。正誤は色だけに頼らず**○／×の形も必ず併記**。**ダークモードは不要**（学校の日中利用／配色2系統の保守コスト／低学年は明るい面の方が図形を追いやすい）。

**アニメーション**：**使うのは transform と opacity だけ**。width/height/top/left/box-shadow/filter のアニメは禁止。押下 `scale(.94)` 80ms、正解バッジのpop 180ms、アイテム取得 400ms、被弾 `translateX(±6px)` 120ms。iPad Safari：`touch-action: manipulation` ／ `-webkit-tap-highlight-color: transparent` ／ `user-select: none` ／ `overscroll-behavior: none` ／高さは `100dvh` ／ `env(safe-area-inset-*)` ／ `backdrop-filter` は使わない／反応は `click` ではなく **`pointerdown`** ／ `prefers-reduced-motion` で全停止。

**効果音7種**（Oscillator＋Gain）：タップ／せいかい／まちがい（小さめ）／アイテム／レベルアップ／被弾／とじる。マスター音量は 0.25（学校用に控えめ）。最初のタップで `audioCtx.resume()`（iOS必須）。**オン・オフは必須**。iPadの消音スイッチで鳴らない前提なので、音は必ず見た目の反応の付属物にする。

**読めない子へ**：`speechSynthesis`（`lang: 'ja-JP'`）を使う。素材ファイル不要でiPadに載っている。問題文の横にスピーカーボタンを常設。ただし**声データが無い端末もある**ので、`getVoices()` が空なら読み上げのボタンを隠す。代わりに、ボタンは絵＋ひらがな2〜4文字、同じ機能は常に同じ位置と色、数は必ず●の集まりを添える（5＝●●●●●）、初回だけ指のアニメでお手本。

**「アプリっぽさ」3つ**：①押した瞬間（pointerdownで色・凹み・音が100ms以内に同時）②画面が重なって動く（横スライド／下からシート220ms、戻りは逆再生）③スクロールしない1画面完結（`position: fixed` ＋ `100dvh`、ゴムバンド無効）

**心配な点**：共有iPadのデータ／SVGの建物が増えるとDOMが増えて60fpsが崩れる（**建物30個を超えたらCanvasへ切替**の線を先に決めたい）／読み上げの声が無い端末・教室の騒音／ひらがなだけでは「ぜんぶで」「のこりは」などの算数のことばが伝わらない（**絵の様式で意味を固定したい**）

## 安全・健康担当の意見（止める役）

**入れてはいけない仕組み**

- ガチャ・ランダムドロップ（出るまで回す＝依存を最も強く作る）
- 連続ログイン・ストリーク（休むと損になり、休めなくなる）
- 順位表・全国ランキング・正答率％（終わりのない比較）
- スタミナの時間回復（回復時刻に端末へ呼び戻す）
- **放置収益・建設待ち時間**（「見に行かないと損」で15分の外に引き戻す）
- 期間限定イベント／今日だけアイテム（取り逃し不安）
- 寸止め演出（あと1問で◯◯、進捗バーを途中で止める）
- 無限モード・コンボ継続（ミスで全消失）
- 終了画面の「つづける」を初期フォーカスにすること
- 通知・リマインド音、消滅カウントダウン
- セーブコードの共有・見せ合い機能（間接的なランキングになる）

**15分の区切り**：0〜1分 今日のめあて1つ／1〜11分 学習／11〜13分 モンスター1体（学習結果で必ず倒せる）／13〜15分 町に1施設＋アバター1箇所。15分で全画面「今日はおしまい」。出すのは**今日できたこと3行**（解いた数・できた計算の名前・町の変化）、明日やること1行、先生・おうち向け1行、**ボタンは「とじる」だけ**。延長は不可。続けたい子には**紙でやる3問**を出す。学習画面には戻れず、見られるのは報酬ゼロの「町の見学」のみ（5分で自動終了）。余り時間の繰り越し・まとめ使いは作らない。

**時間の計り方**：`Date.now()` の差分を1秒ごとに加算して即保存。`document.hidden` ／ blur で停止、**60秒無操作で停止**。日付は端末のローカル日付で、切替は**午前4時**（0時切替は夜更かしの「もう1回」を生む）。端末時刻が前回より前なら当日分は消費済み扱い。**先生モード**：長押し3秒＋先生が初回に決めた4桁。上限を外すのではなく、5/10/15/20/45分から選ぶ**授業タイマーに差し替え**、終了で自動解除。授業モードでは報酬と町づくりを止められる。

**目と体**：1セット（約5分）ごとに**20秒の休憩画面を強制挿入**。連続注視は最大10分。**明滅は1秒3回以下**（原則、明滅演出は使わない）／画面の25%以上を占める明滅・輝度反転は禁止／**赤の明滅は全面禁止**（WCAG 2.3.1・放送ガイドライン準拠）。全画面フラッシュ、揺れ演出、1秒以上動き続ける背景は不可。

**こころ**：間違い＝×や失敗音で止めない。「もうすこし」＋正答＋同型をもう1問。ミス回数は数えず表示しない。**「負け」は作らない**。倒せないときは「にげる」で町へ戻り、持ち物は減らない。レベル低下・町の破壊など後退は無し。3回連続で間違えたら自動で易しくし、**下げたことは表示しない**。「最速」「◯人中◯位」「負け」「ざんねん」は使わず、比べるのは過去の自分だけ。

**個人情報**：ニックネームは**ひらがな・カタカナのみ4文字まで**（漢字不可で姓名を入れにくくする）、既定候補8個から「えらぶ」を初期手段に。「小学校・小・年・組」等を含むなら保存を拒否。セーブコードは**学習記録のみをエンコードし、ニックネームを含めない**。画面表示のみでQR・共有機能は作らない。共有端末は保存枠を最大6つ、各枠に任意の4桁。削除は先生モードのみ。localStorageのキーはニックネームではなく**連番ID**。

**画面に書いておくこと**：「記録はこのiPadの中だけ。どこにも送っていません」「1日15分でおわります。延長はできません」「ガチャ・課金・広告・外部リンクはありません」「ニックネーム以外は入力しません」「気分が悪い・目が疲れたらすぐやめる」「端末を変えると記録は移りません」＋先生モードの入り方と学年末の消去手順。

**いまいちばん危ない点**

1. **「モンスターを倒してアイテム→アバター強化」のドロップを乱数にした瞬間、これはガチャになる。** アイテムは「10問解いたらこれが出る」と事前に明示する固定ドロップ以外は認めない。
2. **町づくりは時間で育つ仕組みと相性がよく、放置収益や建設待ちを入れると15分の外に子どもを呼び戻す装置になる。** 町の変化は学習量だけに連動し、時間経過では1ドットも変わらないこと。

この2点が崩れると、他の対策はすべて無効になる。

## エンジニアの意見

**ファイル構成**（1ファイル30KB以下、全部あわせて300KB以下を目安）

```
index.html            画面の骨組みだけ（約6KB）
css/base.css          色・文字・ボタン（約10KB）
css/screens.css       画面ごとの見た目（約20KB）
js/main.js            起動と画面の切りかえ（約10KB）
js/store.js           保存・読み込み・セーブコード（約12KB）
js/unlock.js          かいほうコードの確認（約4KB）
js/audio.js           Web Audioで音を作る（約8KB）
js/field.js           冒険画面のCanvas描画（約20KB）
js/quiz/choice.js     選択問題 / input.js 入力問題 / order.js 並べ替え（各約6KB）
data/manifest.json    単元の一覧（どのJSONがどの学年・単元か）
data/units/g1-math-01-kazu-10.json  単元ごとの問題
data/unlock-hashes.json  かいほうコードの照合表
sw.js / app.webmanifest / icon.svg  オフライン用
```

JSは `<script type="module">`（標準のしくみ）なのでビルド工程は不要。`docs/study-game/questions/` を原本とし、同期用スクリプトで `public/.../data/units/` へコピー＋形式チェックする。

**問題データJSONの形**

```json
{
  "schemaVersion": 1,
  "unitId": "g1-math-01-kazu-10",
  "grade": 1, "subject": "math", "term": 1,
  "title": "10までのかず",
  "items": [
    { "id": "g1m01-001", "type": "choice", "level": 1,
      "prompt": "りんごは なんこ ありますか。",
      "figure": { "kind": "dots", "count": 7 },
      "choices": ["6", "7", "8"], "answer": 1,
      "hint": "ひとつずつ ゆびで かぞえよう" },
    { "id": "g1m01-002", "type": "input", "level": 2,
      "prompt": "3 と 4 を あわせると いくつ？",
      "answer": "7", "answerKind": "number" }
  ]
}
```

壊れない工夫は3つ。(a) `type` で描き方を選ぶ「登録表」方式にし、知らない `type` はその1問だけ飛ばして残りは遊べる (b) 項目は増やすだけ（既存キーの意味を変えない。変えるときは `schemaVersion` を上げる）(c) `figure` は絵の描き方を名前で指示するだけにして、画像ファイルを持たない。

**単元を足す手順（コードは触らない）**：① `docs/study-game/questions/` に同じ形のJSONを置く → ② `manifest.json` に1行足す → ③ 同期スクリプトを実行

**描画方式**：冒険・バトル・演出＝**Canvas 1枚**（動くものが多く、DOMだと要素が増えるほど重い。解像度は2倍までで打ち止め）。問題文・ボタン・メニュー＝**DOM/CSS**（日本語の折り返し、押しやすさ、読み上げ対応はDOMが有利。動かすのは transform と opacity だけ）。マップ・アイコン・アバター＝**SVG**（拡大してもぼけず容量が小さい）。

**保存データ**：キーは `sg:` で始めて5つに分ける（1つの巨大JSONにしない。壊れたとき全部失うため）。`sg:meta`（schemaVersion・更新日時）／`sg:profile`／`sg:progress`／`sg:srs`（復習予定。上限2000件、あふれたら古い順に捨てる）／`sg:settings`。読み込みは必ず try/catch ＋型チェック。おかしければ `sg:broken:<日時>` に退避して初期値で起動し、「データが読めませんでした。セーブコードはありますか？」と出す。書き込みは1秒まとめ。プライベートブラウズでは書けないので、失敗を検知して1回だけ知らせる。

**セーブコード**：進度だけを載せる（間違い履歴は入れない）。ステージ開放・クリアを1ビットずつのビット列、レベルと所持アイテムを数値にまとめると**約12〜16バイト** → Crockford Base32（`I L O U` を使わない読みまちがえにくい32文字）で **20〜26文字**。4文字ごとにハイフンを入れて表示（例 `H7K2-9MQ4-3TBX-R8W5-2F`）。末尾1文字はチェック文字（CRC-8）で、1文字の打ちまちがえ・隣の入れ替えはほぼ検出できる。**小1には打てないので、使うのは先生か保護者**という前提。同じ文字列を付けたURLをCanvasで自前QR描画（外部通信なし）し、カメラで読ませる道も用意できる。

**かいほうコード**：**サーバーなしでは改ざんを完全には防げない**（JSを読めば答えが分かる）。狙いは「小学生がうっかり先に進めない」程度に置く。先生が入力した文字を正規化（全角→半角、カタカナ→ひらがな）→ Web Crypto の SHA-256 で要約 → 先頭10桁を照合表と比べる。表にはハッシュだけ入るので、ファイルを見ても元の文字列は読めない。先生が覚えやすい形は **`さくら32`**（春＝さくら、3＝ステージ3、2＝クラス）。Web Crypto は `https` か `localhost` でないと動かないので、動作確認はPowerShellの簡易サーバーで行う（`file://` は不可）。

**オフライン対応**：PWAにする。Service Worker を `public/study-game/sw.js` に置くと効く範囲が `/study-game/` 以下に限られ、サイト本体に影響しないので好都合。**Next.js の落とし穴：`public/study-game/index.html` は `/study-game/index.html` でしか開けず、`/study-game/` では404になる**（rewriteを1本足すか、リンク先をファイル名まで書く）。更新が届かない問題はキャッシュ名に版を入れ、古い版を消す。問題JSONは「まずネット、だめならキャッシュ」、本体は「まずキャッシュ」。iOSはホーム画面に追加していないサイトのデータを長く使わないと消すことがあるので、セーブコードが保険になる。

**初回読み込み**：初回は index.html ＋ CSS ＋ main.js ＋ manifest.json ＋ 最初の単元1つだけ（合計150KB以下を目標）。冒険画面・問題形式ごとのJSは画面を開くときに読む。フォントは端末の標準を使い、フォントファイルは置かない。

**iPad Safari の注意**：`pointerdown` で反応（`click` は待ちが入る。二重発火を防ぐためどちらか一方に統一）／`touch-action: manipulation`（`maximum-scale` での拡大禁止は使わない。拡大が必要な子がいる）／音は**最初のタップの中で** AudioContext を作って `resume()`（スタート画面に「おす」ボタンを必ず置く）／高さは `100dvh` ＋ `env(safe-area-inset-*)` ／`overscroll-behavior: none` ＋本体を `position: fixed` ／**画面の回転はWebから固定できない**ので縦横どちらでも成立する配置にする／低電力モードでは30fpsに落ちるので、経過ミリ秒で動かす作りにして遅くても壊れないようにする。

**心配な点**：かいほうコードの改ざんは原理的に防げない／iOSの容量整理やSafariの設定でデータは消える（学期末に「セーブコードを紙に貼る」運用）／manifest.json が数百行を超えたら学年別に分割／**Web Audioの作り物の音は素朴**になる（最初は効果音だけに絞る）／OneDrive＋並走セッションでビルドやブランチの取り合いが起きる（scratchpad に git worktree を作って作業する）／既存ツールと違い複数ファイルなので、**ハードリンクは使わず**コピー＋検証スクリプトに統一するほうが安全
